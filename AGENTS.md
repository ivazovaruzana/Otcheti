# KPI To-Do — контекст для независимой проверки (Codex)

Этот файл дублирует правила из `CLAUDE.md`, чтобы другой агент мог проверить
работу, не читая историю диалога.

## Проект

Учебное одностраничное приложение для личных KPI-целей.

Пользователь — руководитель административной группы. 4 личные цели на полугодие.
Заходит раз в неделю перед статус-встречей: смотрит список целей, раскрывает
нужную, отмечает выполненные подзадачи, добавляет и удаляет подзадачи,
сверяется со сроками. Заход — до 5 минут.

Стек: React + Vite, хранение в localStorage. Без сервера, без авторизации,
без внешних API.

## Правила работы

- Небольшие этапы. Перед изменениями — план и подтверждение.
- После каждого этапа — запуск приложения и проверка одного сценария целиком.
- Jira подключена только на чтение через локальный MCP `banki-jira`; в Jira
  ничего не создаётся и не меняется. Из приложения запросов в сеть нет —
  снимок обновляется вручную.
- n8n, Loop, другие внешние сервисы и серверная часть — только после
  отдельного подтверждения.
- Секреты, токены и ключи не хранятся в файлах проекта. Токен Jira лежит в
  Windows Credential Manager, `.env` — в `.gitignore`.
- Данные: `data/kpi_h2_2026.json` — снимок собственных KPI-целей пользователя
  из Jira; чужих персональных данных, контактов и сумм в проекте быть не должно.
  `data/kpi_h2_demo.json` — вымышленный образец формата.

## Что проверять при ревью

1. В репозитории нет токенов, ключей, паролей, `.env` с реальными значениями.
2. Нет обращений к сети: `fetch`, `axios`, вызовы внешних API.
3. Нет серверного кода и зависимостей от бэкенда.
4. `data/kpi_h2_2026.json` содержит только задачи, назначенные пользователю
   (контейнер KPI-29563); формат дат `YYYY-MM-DD`; `data/kpi_h2_demo.json`
   вымышленный.
5. Приложение переживает перезагрузку страницы: состояние берётся из
   localStorage.
6. Крайние случаи не ломают вёрстку: подзадача без срока и подзадача с очень
   длинным названием.
